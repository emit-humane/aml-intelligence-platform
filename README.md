# AML Intelligence Platform

> Real-time Anti-Money Laundering detection with a 4-layer ML pipeline: Rule Engine → Graph Analytics → Behavioral Anomaly → Temporal GNN.

**Team Bazooka | iDEA 2.0 | PS3: Fund Flow Tracking**

---

## Problem Statement

Traditional AML monitoring is batch, reactive, and overwhelmed by false positives (90–95% of alerts are noise). This platform demonstrates that a layered ML approach — combining deterministic rules, graph topology, behavioral anomaly detection, and temporal GNN scoring — can detect 10 AML typologies in real time with explainable, analyst-ready alerts.

See [`docs/D1_problem_solution_brief.md`](docs/D1_problem_solution_brief.md) for the full problem + solution brief.

## How to Run Locally

### Prerequisites

- Python 3.11 (or `uv python install 3.11`)
- Node.js 18+
- `uv` ([install](https://docs.astral.sh/uv/))

### Setup

```bash
# Clone
git clone https://github.com/<your-org>/aml-intelligence-platform.git
cd aml-intelligence-platform

# Copy env template
cp .env.example .env

# Install all dependencies (Python venv + npm)
make install
```

### Full Demo (end-to-end in ~10 minutes)

```bash
make demo
```

This runs in sequence:
1. `make clean` — clear old data
2. `make generate` — synthesise 500K transactions with 10 AML typologies
3. `make train-offline` — train L3 behavioral models + L4 GNN (~6 min)
4. Start FastAPI on port 8000
5. Replay stream transactions at 50 tx/sec
6. `make evaluate` — compute blind evaluation metrics

### Individual Targets

```bash
make generate          # System 1: generate synthetic data
make train-offline     # System 2 offline: train L3 + L4 models
make serve             # Start API on :8000 (auto-reload)
make frontend-dev      # Start Next.js dashboard on :3000
make evaluate          # System 3: run blind evaluation
make clean             # Remove generated data + artifacts
```

### Manual step-by-step

```bash
# 1. Generate data
python -m scripts.run_generator --config config/generator_config.json

# 2. Train models
python -m scripts.run_offline_pipeline

# 3. Start API
uvicorn system2_platform.api.main:app --reload --port 8000

# 4. Start dashboard
cd frontend && npm run dev

# 5. Smoke-test a transaction
curl -X POST http://localhost:8000/stream/transaction \
  -H "Content-Type: application/json" \
```

## Dataset

All data is **fully synthetic** — generated by System 1 using a configurable stochastic model. No real bank data is used anywhere.

**Generation parameters (default):**

| Parameter | Value |
|-----------|-------|
| Accounts | 5,000 |
| Historical transactions | ~500,000 |
| Stream transactions | ~50,000 |
| Fraud rate | ~3.5% |
| AML typologies | 10 (structuring, circular laundering, layering chains, fan-in/fan-out, fraud rings, dormant activation, velocity bursts, cross-border layering, round-tripping) |
| Date range | 2020-01-01 – 2024-12-31 |

To regenerate: `make generate` (or `python -m scripts.run_generator --config config/generator_config.json`).

## Known Limitations

1. **Synthetic data only.** Real-world performance will differ due to concept drift, feature distribution shift, and reporting bias inherent in real SAR data.
2. **Single-machine deployment.** The in-memory graph and feature store do not scale horizontally. A production deployment would require graph sharding (Neo4j/TigerGraph) and a message queue (Kafka).
3. **No authentication.** The dashboard is open — this is a hackathon demo. Adding OAuth/OIDC is a one-sprint effort.
4. **No privacy-enhancing technologies.** Federated learning and differential privacy are mentioned in the research literature but are out of scope for this POC.
5. **Alert storage is in-memory.** Alerts do not survive API restarts. The SQLAlchemy model is in place but Postgres integration requires `docker-compose up`.
6. **GNN retraining is manual.** The TGN memory degrades over time as account behaviour shifts. Production would require periodic re-training triggered by concept drift detection.
